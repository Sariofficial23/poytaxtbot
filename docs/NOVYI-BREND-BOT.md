# ЗАДАНИЕ ДЛЯ CLAUDE CODE: новый бот доставки для другого бренда

> **Как пользоваться (для человека):**
> 1. Создайте на GitHub **пустой приватный репозиторий** для нового бренда (например `burgerhouse-bot`) и откройте его в Claude Code (claude.ai/code).
> 2. Прикрепите **этот файл** и **файлы логотипа** (PNG, JPG, SVG, PDF или .cdr — любой формат).
> 3. Впишите название в блок «Данные бренда» ниже (или просто напишите его в сообщении) и отправьте: *«Сделай бота по этому файлу»*.
> 4. Меню (PDF, фото меню, Excel, текст) можно приложить сразу или прислать, когда Claude Code попросит. Цены можно не давать.

## Тебе, Claude Code: что сделать

Ты делаешь **копию готового бота доставки Poytaxt** под новый бренд. Бот не пишется заново: берётся рабочий проект и меняется «вывеска» — название, логотип, цвета, тексты, меню. **Все функции остаются без изменений.**

Исходный проект: **`sariofficial23/poytaxtbot`**, ветка **`main`** (публичный; клонируй через `git clone`, при необходимости подключи через add_repo). В нём лежат подробный гайд `docs/GUIDE-novyi-bot.md` и промпты `docs/PROMPTS.md` — прочитай гайд перед началом, он — источник правды по деталям.

**Язык общения с человеком — русский.** Человек не программист: объясняй простыми словами, по шагам, что нажать. Никогда не проси прислать токены, пароли или строки подключения к базе в чат.

### Что умеет бот (должно работать после копии — ничего не удалять)

- **Telegram-бот** (`backend`, Node.js + Express + Prisma + PostgreSQL): `/start` с кнопкой мини-аппа, `/id` для ID группы, заказы в группу курьеров с кнопками «✅ Men olaman» → «🏁 Yetkazildi» (нажать может только взявший курьер), уведомление клиенту о доставке, keep-alive (сервер сам себя будит).
- **Мини-апп** (`mini-app`, React + Vite): главная с баннерами, категории, меню, карточка блюда, корзина, промокоды, бесплатная доставка от порога, апселл Coca-Cola, профиль с заказами. Телефон +998.
- **Админка** (`admin-panel`, React + Vite): заказы (просроченные >10 мин — красный пульс), товары, **стоп-лист** (кнопка «В наличии / Стоп-лист»), баннеры, промокоды, отчёт по курьерам, настройки доставки, проверка группы курьеров.
- **Блюда с ценой 0 и в стоп-листе скрыты** в мини-аппе, заказать их нельзя (проверка на сервере). Меню можно заливать без цен — владелец ставит цены в админке.
- Таблицы базы создаются сами при запуске (`ensureDatabase`), новые колонки добавляются сами.

## Порядок работы

### Шаг 1 — Копия проекта

1. Скопируй из `sariofficial23/poytaxtbot` (ветка `main`) в текущий репозиторий: папки `backend`, `mini-app`, `admin-panel`, `branding`, `docs`, файлы `render.yaml`, `README.md`, `.gitignore`. **Без** `node_modules`, `dist`, `.git`.
2. Закоммить и запушь в ветку **`main`** этого репозитория (если работаешь в другой ветке по правилам сессии — запушь и туда, и попроси у человека разрешение на `main`: Render и Vercel берут код из `main`). Напомни человеку: GitHub → Settings → General → **Default branch = `main`**.

### Шаг 2 — Название

Обозначения: `BRAND` = название как есть (например `Burger House`), `slug` = латиница, нижний регистр, без пробелов (например `burgerhouse`).

1. Замени «Poytaxt» на `BRAND` во всех местах:
   - `backend/src/config/default.js` (`botName`)
   - `backend/src/core/bot.js` (текст `/start`)
   - `mini-app/src/screens/Home.jsx`, `mini-app/src/components/Onboarding.jsx`, `mini-app/index.html`
   - `admin-panel/index.html`, `admin-panel/src/pages/Login.jsx`, `admin-panel/src/components/Sidebar.jsx`
   - `README.md`, `docs/*` (в гайде можно оставить упоминание, что основа — Poytaxt)
2. Имена `poytaxt-backend`, `poytaxt-mini-app`, `poytaxt-admin-panel` → `slug-backend`, `slug-mini-app`, `slug-admin-panel` в трёх `package.json`, трёх `package-lock.json` и `render.yaml`.
3. Тексты приветствия — **под фастфуд**, на узбекском (латиница), как сейчас. Например в Onboarding: *«Sevimli burger va fastfud — bir necha bosishda»*; в `/start`: `ga xush kelibsiz 🍔`. Подбери эмодзи и слова под реальное меню бренда.
4. В конце проверь поиском: `grep -rni "poytaxt" --exclude-dir=node_modules --exclude-dir=.git .` — в коде не должно остаться (кроме упоминания основы в docs).

### Шаг 3 — Логотип

Логотип прикреплён к сообщению. Любой формат:
- **.cdr (CorelDRAW):** `apt-get install -y libcdr-tools librsvg2-bin` → `cdr2xhtml` → вытащи `<svg:svg>` в отдельный SVG (убери префикс `svg:`, дубли атрибутов `xmlns`), отрендерь `rsvg-convert`. Градиенты из CDR часто конвертируются криво (уходят в белый) — тогда перекрась логотип в сплошной фирменный цвет, убери белую обводку (`stroke: #ffffff` → `none`).
- **PDF:** `pdftoppm` / `pdfimages`. **PNG/JPG/SVG:** как есть.

Сделай (ImageMagick `convert`):
| Файл | Куда | Что |
|---|---|---|
| `logo.jpg` 512×512 | `mini-app/public/`, `admin-panel/public/` | полный логотип по центру на фирменном фоне |
| `logo-mark.jpg` 512×512 | `mini-app/public/`, `admin-panel/public/` | **монограмма** (первая буква или знак из логотипа) — для маленьких мест: шапка мини-аппа 54px, сайдбар админки. Полное название там не читается |
| `favicon.png` 64×64 | `mini-app/public/`, `admin-panel/public/` | монограмма |
| `bot-avatar.jpg` 512×512 | `branding/` | аватар для BotFather |
| логотип в обычных форматах | `branding/` | SVG (если есть вектор, `viewBox` обрезан по логотипу), PNG без фона (высокое разрешение), PNG на фирменном фоне, квадратный JPG 2048×2048 |

Удали из `branding/`, `mini-app/public/`, `admin-panel/public/` все старые файлы Poytaxt. Покажи человеку превью логотипа и монограммы картинкой и пришли файлы из `branding/`.

### Шаг 4 — Дизайн (сначала показать — потом менять код)

Все цвета мини-аппа — в **одном блоке `:root`** в `mini-app/src/styles.css` (переменные `--red` акцент кнопок и цен, `--bg` фон, `--card`, `--text`, `--title`, `--muted`, `--border`, `--on-accent` текст на кнопках, `--pattern` узор фона и др.).

1. Возьми фирменные цвета из логотипа (и из меню, если оно приложено — например `convert … -format %c histogram:info:`).
2. Сделай **3 варианта** темы (только переопределение `:root`, без правок кода): например светлый, тёмный, светлый с цветной шапкой. Для фастфуда уместны яркие, «аппетитные» цвета; узор фона — под стиль бренда или без узора.
3. Запусти мини-апп на тестовых данных: простой mock-сервер на Node (`/api/products`, `/api/banners`, `/api/settings`, `/api/orders/my`, `/api/menu-img/*`) + `VITE_API_URL=http://localhost:PORT npx vite`, скриншоты Playwright (Chromium: `/opt/pw-browsers`, viewport 390×844, `localStorage.dk_onboarded=1` чтобы пропустить приветствие). Собери в одну картинку с подписями A / B / C и покажи человеку. Цены на скриншотах — условные, скажи об этом.
4. **Жди выбора.** После выбора примени тему в `:root` и синхронно:
   - цвет шапки Telegram: `mini-app/index.html` (`theme-color`), `mini-app/src/telegram.js` (`setHeaderColor`, `setBackgroundColor`) = `--bg`;
   - `GRADIENTS` в `mini-app/src/format.js` и `COLORS` в `admin-panel/src/pages/Banners.jsx` (одинаковые);
   - акцент админки `--red` / `--red-soft` в `admin-panel/src/styles.css` (админка светлая — акцент нужен тёмный/насыщенный, чтобы читался на белом);
   - если фон тёмный — проверь контраст логотипа на приветствии (`.onb-logo` — рамка цветом акцента).
5. Сделай скриншоты готовых экранов: приветствие, главная, меню, карточка блюда, корзина. Покажи человеку.

### Шаг 5 — Меню

Если меню не приложено — попроси его (PDF макета, фото меню, Excel или текст «Категория — Название — Цена»). Если человек хочет без меню — оставь `items = []` и скажи, что блюда добавляются в админке (Товары → Добавить).

Меню — в `backend/src/models/menu.data.js`. **Сохрани структуру файла** (`photoUrl`, `items`, `PHOTOS`, `export const MENU = items.map(...)` без фильтра по цене). Формат: `[КАТЕГОРИЯ, 'Название', цена]`, цена `0` = нет цены (блюдо скрыто, пока владелец не поставит цену в админке).

1. Категории — в порядке, как в меню (порядок в мини-аппе = порядок первого появления).
2. Названия — **точно как в меню**; если исправляешь опечатки или уточняешь (например «Куриный» → «Шашлык куриный») — покажи список правок.
3. Цены — из меню; если в меню их нет или человек сказал «оставь пустыми» — `0`. Если на снимках ценники написаны от руки и плохо читаются — поставь лучшее прочтение и **явно спроси**.
4. Удали все старые фото из `backend/public/menu/`.
5. Фото: из PDF меню вытаскивай оригиналы `pdfimages -png` (а не скриншот страницы), сопоставь с блюдами (сделай контакт-лист `montage -label '%f'` и посмотри), обрежь `convert … -resize 800x800^ -gravity center -extent 800x800 -quality 82`. Узкие/высокие фото (стакан напитка) — не обрезай, а впиши в квадрат с фоном. **Фото со снимков телефона не используй, если человек так сказал.**
6. Проверка скриптом: каждый файл из `PHOTOS` существует, лишних файлов нет, нет дублей названий, каждый ключ `PHOTOS` есть в `items`.
7. Дай человеку список: **блюда без фото** и **блюда без цены**.

### Шаг 6 — Проверка и пуш

- `npm install` и `npm run build` в `mini-app` и `admin-panel` — без ошибок.
- `backend`: `npm install`, `npx prisma validate`, `node --check` на изменённых файлах.
- По возможности — прогон бэкенда на локальном PostgreSQL (`apt-get install postgresql`): `/health`, `POST /api/admin/seed` (заголовок `X-Admin-Password`), `/api/products` (только блюда с ценой > 0 и в наличии).
- Закоммить понятными сообщениями и запушь в `main`.

### Шаг 7 — Дай человеку инструкцию по запуску

Когда код готов, выдай человеку **пошаговую инструкцию** (своими словами, по разделам 7–14 гайда `docs/GUIDE-novyi-bot.md`), подставив название бренда. Обязательно включи эти правила — на них уже были реальные поломки:

1. **@BotFather** → `/newbot`, имя `BRAND`, username на `bot`. Токен — **только в Render, никогда в чат**. Аватар — `branding/bot-avatar.jpg`. **У каждого бренда свой бот и свой токен.**
2. **Neon** (почта бренда) → проект `slug`, регион Frankfurt, Connection pooling → `DATABASE_URL`; compute 0.25 CU.
3. **Render — ⚠️ ОТДЕЛЬНЫЙ аккаунт на почту бренда, не общий.** Один бесплатный аккаунт = 750 часов в месяц = **один бот**. Если на одном аккаунте 2+ бота — примерно к середине месяца все останавливаются, мини-апп пишет «Failed to fetch». New → Blueprint → репозиторий, ветка `main`. Переменные: `DATABASE_URL`, `BOT_TOKEN`, `ADMIN_PASSWORD`, `MINI_APP_URL=0`, `COURIER_GROUP_ID=0`. Проверка: `…onrender.com/health` → `{"status":"ok"}` («Cannot GET /» на главной — это нормально, сервер жив).
4. **Vercel — два проекта** из репозитория: Root Directory `mini-app` и `admin-panel`. **Application Preset = Vite** (Vercel иногда сам ставит «Services» → «No detected services» → не соберётся). `VITE_API_URL` = адрес Render **без «/» в конце**, тип переменной **Config** (не Secret — `VITE_`-переменные Vercel секретными не сохраняет). Production Branch = `main`. После смены переменной — **Redeploy без Build Cache**.
5. **Связать:** Render → `MINI_APP_URL` = адрес мини-аппа; BotFather → Bot Settings → Menu Button → адрес мини-аппа, текст `Menyu`.
6. **Группа курьеров:** ⚠️ **сначала добавить бота в группу** и сделать админом (иначе заказы не приходят), потом `/id` в группе → `COURIER_GROUP_ID` с минусом. Проверка: админка → Настройки → «Проверить группу курьеров».
7. **Админка:** Товары → **«Обновить меню» — один раз**, при первом запуске (пока не нажали — меню в мини-аппе пустое). Потом **больше не нажимать**: кнопка перезаписывает все товары, цены, фото и стоп-лист из админки. Поставить цены блюдам «Нет цены», настройки доставки, баннеры, промокоды.
8. **Тестовый заказ** — вся цепочка: группа → «Men olaman» → «Yetkazildi» → сообщение клиенту → заказ в админке; стоп-лист скрывает блюдо.
9. **UptimeRobot** на `…/health`, интервал 5 минут.
10. **Если «Failed to fetch»:** проверить `/health`; если сервер жив — мини-апп собран со старым адресом (Ctrl+U → файл `/assets/index-….js` → Ctrl+F `onrender` покажет, какой адрес внутри) → исправить `VITE_API_URL` → Redeploy без кэша → полностью закрыть мини-апп в Telegram.

Попроси человека присылать адреса Render и Vercel и скриншоты ошибок — и веди его по шагам до рабочего тестового заказа. В конце — чек-лист сдачи клиенту (раздел 18 гайда).

## Правила

- Не удаляй и не «упрощай» функции бота. Меняется только вывеска, тексты, цвета, логотип и меню.
- Код дизайна меняй **только после выбора** человеком варианта.
- Перед каждым пушем — сборка без ошибок.
- Не выдумывай цены и названия: что не прочитал — спроси.
- Никаких секретов (токены, пароли, `DATABASE_URL`) в коде, коммитах и чате.
